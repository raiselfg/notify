# Отправка веб-пушей

`PushSender(settings).send(subscription, message, expires_at)` выполняет одну
попытку. При создании отправщика проверяется наличие VAPID-конфигурации.
`expires_at` должен содержать часовой пояс. Сообщение шифруется в `aes128gcm`,
запрос подписывается VAPID. Шифрование выполняется в потоке, HTTP — асинхронно.

`PushMessage` содержит `version`, `event_id`, `task_id`, `title`, `body`.
Поля `url` (`/tasks/{task_id}`) и `tag` (`task-{task_id}`) формируются сервером.
Клиенту потребуется поддержать этот формат и путь перехода.

Отправщик возвращает `PushResult`:

| Статус | Значение |
| --- | --- |
| `accepted` | Push-сервис принял запрос (`200–202`); показ не подтверждён |
| `invalid_subscription` | Push-сервис вернул `404/410` |
| `retry` | Таймаут, сетевая ошибка, `429` или `5xx` |
| `failed` | Некорректные данные, небезопасный адрес, остальные HTTP-ответы |
| `expired` | До конца актуальности осталось менее секунды |

Результат содержит HTTP-код при наличии ответа, задержку `retry_after_seconds`
для временной ошибки и безопасную причину `reason` для локального сбоя.
Тела ответов, endpoints и ключи в результат не включаются.

`PUSH_TIMEOUT_SECONDS` ограничивает попытку после получения слота отправки.
TTL ограничивается `PUSH_TTL_SECONDS` и оставшимся сроком актуальности события.
`PUSH_MAX_CONCURRENCY` ограничивает параллельные попытки на экземпляр отправщика
(по умолчанию 10, допустимо 1–100). Используйте общий экземпляр в процессе.
Публичный VAPID-ключ задаётся в окружении фронтенда; API выдачи ключа отсутствует.

Для отправки на сохранённые подписки пользователя используйте
`PushDeliveryService(session, sender).send_for_user(user_id, message, expires_at)`.
Метод возвращает результаты по ID подписок. Ему нужна отдельная сессия БД:
чтение завершается до сетевых запросов, очистка выполняется отдельной транзакцией.
После `404/410` удаляется только та версия подписки, которая использовалась при
отправке: проверяются ID, владелец, endpoint, ключи и время обновления. Сбой одного
устройства не препятствует отправке на другие. Старые записи с некорректными
ключами получают `failed` без отправки и автоматического удаления.

HTTPS и проверка сертификатов обязательны; дополнительные HTTPS-порты разрешены.
Непубличные и multicast IP отклоняются, в том числе в результате DNS-разрешения.
Соединение использует проверенный DNS-результат. Редиректы и прокси из окружения
отключены, чтобы адрес клиента не позволял обратиться к внутренней сети.

Этот этап не создаёт очередь, не проверяет состояние задачи и не запускает
напоминания автоматически. Планировщик и устойчивые повторы будут добавлены
отдельно. Нельзя повторять всю рассылку из-за сбоя одного устройства: повторять
нужно только соответствующую доставку с учётом её срока актуальности.

В `typings/` описаны используемые методы библиотек без полных аннотаций.
Тесты проверяют подпись и расшифровку сообщения, статусы, TTL, таймаут,
параллелизм и очистку подписок. HTTP и DNS подменены; реальных отправок нет.
